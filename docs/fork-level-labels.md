# 等级标签设置

管理员在「等级标签」页签开启或关闭等级，编辑最低评论数和标签名称。
门槛从 0 开始，严格递增，支持 1–20 档；名称最多 40 个字符，允许留空。

保存位置为 `/app/runtime/level-settings.json`，可通过 `LEVEL_SETTINGS_FILE` 指定。
Docker 部署需要持久化并允许 node 用户写入 `/app/runtime`。
没有保存文件时沿用 `LEVELS` 环境变量；保存后网页配置优先，包括显式关闭。
修改在后续评论列表请求中生效，无需重建镜像或迁移数据库。

名称优先级：客户端显式 `locale.levelN` → 后台名称 → 客户端默认语言名称 → `Level N`。
后台名称作为自定义内容原样显示，不自动翻译。多语言站点可留空，或在客户端覆盖。
客户端必须更新到支持 `levelLabel` 的版本；旧客户端仍能显示等级，但继续使用本地名称。
博客当前保存的客户端快照不会随服务端发布自动更新，需另行更新快照或接入发布包。

统计沿用公开评论及回复、排除待审核和垃圾评论的规则；MySQL 下排除私密评论。
历史评论显示当前等级，并非首次评论的永久标识。标签仍以文本渲染。

等级设置与 IP 管理新增文案均走管理端语言资源。提供简体中文、繁体中文及英文，
其他管理端语言在这些新增项上回退英文。用户填写的标签文本不受后台语言切换影响。
